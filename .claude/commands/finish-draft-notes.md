Execute `/finish-draft-notes [--batch-size N] [--target youtube|podcast|both]`:

> [!warning] There is no `--parallel` flag, deliberately — same reasoning as `/process-raw-transcripts` (2026-07-26 rate-limit incident, see `buglog.md`). One single sequential agent, never per-file dispatch.

> [!info] **Model tiering (same idea as `/process-raw-transcripts`, applies identically here).** Since the batch runs as one orchestrating agent's own sequential loop, tiering means picking that agent's model tier before the batch starts, based on the *drafted* batch's composition — which is easier to gauge here than in `/process-raw-transcripts` because the draft JSONs already carry a `signal_density_guess` per file (see the warning above: that guess runs hot on "high," so treat it as a rough composition signal for tier selection, not a promise). A batch of drafts that are mostly short/`low`-or-`mixed`-guessed and straightforward can run under a lighter/faster tier; a batch weighted toward podcasts, long-form episodes, or files guessed `high` density should launch with Sonnet or higher. **The tier never changes what step 2 requires of any individual file**: confirming/correcting the draft's signal-density guess, re-verifying every quote against the actual transcript (a draft quote passing the script's mechanical substring check is not the same as it being contextually accurate — see the warning above), and the full anti-fabrication bar all apply exactly the same regardless of tier. A lighter tier only bets on faster routine throughput for a batch expected to be light; if a file turns out denser or its draft guess turns out wrong, do the fuller work anyway rather than under-serving the note because of the tier picked for the batch as a whole.

> [!info] **What a draft actually is, and isn't.** `scripts/generate_draft_notes.py` runs `qwen2.5:14b` (local, on the CachyOS machine) against a raw transcript and writes a structured scaffold to `Research/*/Raw/.drafts/<video_id>.json`: a relevance guess, a signal-density guess, themes, key points, and quotes. **Per the real Phase 5 A/B validation (2026-08-15, 9 videos against Claude's own already-written notes): this model's signal-density judgment matched Claude's only 3/9 of the time (systematically over-rating density), and only 13/26 of its claimed-verbatim quotes were genuinely exact substrings of the source** (the other half were rejected by the script's own programmatic verbatim gate before ever reaching the draft file — so every quote actually present in a draft has already passed that mechanical check, but a mechanical substring match is not the same guarantee as "this is what the speaker meant in context," so don't skip judgment entirely). A draft is a **reading aid that cuts how much of the raw transcript you need to read closely**, not a pre-approved note. Treat `signal_density_guess` as a hypothesis to confirm or correct, not a fact — the draft file's own `signal_density_confirmed: false` field exists specifically to flag this.

## 1. Find drafted-but-unfinished files
Read `Research/YouTube/Raw/.drafted_ids.json` and/or `Research/Podcasts/Raw/.drafted_ids.json` (per `--target`) — every entry there has a `draft_file` pointing into `.drafts/`. Cross-check against `.processed_ids.json` in the same directory: a video already `ok`/`skipped-*` in `.processed_ids.json` is already finished, skip it (this can happen if a manual `/process-raw-transcripts` run touched it before this command did). Default `--batch-size 20` if not specified.

Also run `python scripts/find_cross_stream_duplicates.py` first, same as `/process-raw-transcripts` step 1 — zero-cost, keeps the dedup cache fresh.

**Also run `python scripts/find_repeat_candidates.py`** (added 2026-08-20, idea #3) — zero-Claude-cost, writes `Research/.repeat_candidates.json`: for every unprocessed item, a same-channel existing note it likely already covers (keyword/tag overlap, never cross-channel). This is a **different thing from the dedup check above** — dedup finds the *same recording* published twice; this finds a *different video from the same creator covering ground they've already covered before*. See step 2's repeat-content handling below for how to use it.

## 2. Per-video finishing step, single agent, sequential
For each drafted video in the batch:

- **Read the draft JSON first** (`themes`, `key_points`, `notable_quotes_verified`, `signal_density_guess`, `relevant`, `relevant_confidence`, `structure_map`, `known_low_value_pattern`) — this is your fast orientation, not your source of truth for the note body.
- **Read the transcript — the `lite_file` by default, not `source_file`** (added 2026-08-20, idea #2). Every draft carries a `lite_file` (`Research/*/Raw/.lite/<id>_lite.txt`) — a derived copy with only zero-meaning-risk filler mechanically stripped (exact 3+ word stutters, standalone "um"/"uh" tokens, exact-duplicate consecutive sentences; see `collector_common.strip_filler_text`'s docstring for the exact conservative rules). Read this one first — it's meaningfully shorter for the same real content. **Fall back to `source_file` (the real untouched raw transcript)** whenever something looks truncated, ambiguous, or a sentence reads oddly cut — and always for the *final* check on any quote you're about to put in the note: a quote must be verified against `source_file`, never only against `lite_file`, before it goes in `## Notable Quotes` (the draft's own `notable_quotes_verified` entries were already checked against the real source file by the script, so those specifically don't need a second re-read for this purpose — this fallback rule is about anything you pull yourself while reading the lite copy).
- **`structure_map` is a reading-effort hint, not a fact** — same status as `signal_density_guess`: the draft's `structure_map_confirmed: false` field means unconfirmed. Each entry gives a `[start, end)` char range into `lite_file` and a guessed `substantive`/`filler`/`sponsor`/`tangent` label. Use it to prioritize where you read closely vs. skim, but don't skip a `filler`/`tangent`-labeled range outright — spot-check it briefly, since this is the same local model whose signal-density judgment runs hot; a real point can hide in a range it mislabeled.
- **Dedup check** — same three-stage process as `/process-raw-transcripts` step 2 (check `Research/.dedup_candidates.json` first, cheap metadata fallback, content spot-check only if genuinely ambiguous). If confirmed duplicate: mark `processed_ids[video_id] = {"status": "skipped-duplicate-of-<youtube|podcast>"}` in the real `.processed_ids.json`, remove the entry from `.drafted_ids.json`, delete the draft file, move on.
- **Repeat-content check** (added 2026-08-20, idea #3 — Ross's explicit refinement: **never skip, only calibrate effort**). Look up this `video_id`/`episode_guid` in `Research/.repeat_candidates.json` (generated in step 1). If flagged (`likely_repeat_of` points at an existing same-channel note): still process this file fully, same as any other — but apply the vault's existing content-fidelity discipline (same framing as the resistant-starch/content-fidelity-remining precedent, development.md's 2026-08-17 "Content-fidelity sweep" entry): do a **fast cross-check** confirming the claims that overlap with `likely_repeat_of` still match what's already documented (rather than a full independent re-extraction of ground already covered), then spend your **real extraction effort specifically on what's NEW** in this video that the existing note doesn't have — a different framing, an updated number, a claim the creator hadn't made before, etc. A `"high"` `confidence` repeat still gets this same treatment, just with more confidence the fast-cross-check portion will be quick; `"medium"` warrants a bit more skepticism that it's actually a repeat at all before leaning on the shortcut. If the video turns out to add nothing new beyond what's already in `likely_repeat_of`, that's still a real, reportable finding for the batch summary — not a reason to under-write the note itself.
- **Confirm or correct relevance** — the draft's `relevant` guess is usually right (this is a coarser judgment than signal-density and the model does better at it) but verify against the actual transcript, especially for anything the draft flagged as borderline or `relevant_confidence: "low"`. **`known_low_value_pattern: true`** (added 2026-08-20, idea #4 — a deterministic, non-LLM flag: real channel/title patterns this vault has already confirmed low-value, e.g. Kinobody, the boxing/MMA-technique channel list, bare lift-log or giveaway/announcement titles — see `low_value_pattern_reasons` for which one matched) plus a `relevant_confidence: "high"` from the model together mean the confirmation pass can move fast — but it's still a real confirmation, never a blind skip, same as this file's own standing rule for `relevant`. A `known_low_value_pattern: true` with the model itself uncertain (`relevant_confidence: "medium"`/`"low"`), or no pattern match at all, gets the normal full-attention check. Off-topic → `processed_ids[video_id] = {"status": "skipped-irrelevant"}`, remove from `.drafted_ids.json`, delete the draft file.
- **Confirm or correct signal-density** — treat the draft's guess as a starting hypothesis. Given the measured bias toward over-rating density, be specifically skeptical of a `"high"` guess on a short or clearly-thin video — check it against the actual substantive-content-to-runtime ratio yourself, same criteria as `/process-raw-transcripts` step 2's signal-density section. Same three-tier depth scaling applies (`high`/`mixed`/`low` — see that command for the exact per-tier structure, unchanged here). This confirmed value is also the honest read on whether the batch's up-front model-tier choice (see the callout above) matched reality — note it for next time, but it does not retroactively change the verification/quote/anti-fabrication bar applied to this file.
- **Key points**: the draft's list is a real starting point (its own hallucination risk on plain factual summarization is much lower than on verbatim quoting), but verify against the transcript rather than copying blind — check for anything the model missed, anything it got subtly wrong, and confirm promotional/sponsor content was correctly excluded.
- **Quotes**: `notable_quotes_verified` already passed a mechanical exact-substring check against the source transcript (see the warning above) — but re-confirm each one actually says what it appears to say in context, and feel free to pull additional/better verbatim quotes directly from the transcript yourself if the draft's selection is thin or the video is `high` density and warrants more than the draft's 2-5 candidates. Never add a quote you haven't personally verified against the actual transcript text, draft or not.
  > [!warning] **Exact-substring-verified is not the same as "makes sense."** Confirmed real case (2026-08-28 A/B pipeline test, see `development.md`): a draft's `notable_quotes_verified` entry passed the substring check but was a whisper-mangled technical term ("DHA and pregnant along" for what was almost certainly "DHEA and Pregnenolone") — nonsense in isolation despite being a genuine exact substring. The draft model has no coherence check, only the script's mechanical one. Before accepting any `notable_quotes_verified` entry as-is (this applies doubly to any file whose raw header says `transcript_method: local whisper`), read it in context and confirm it's coherent prose, not just present in the source. If it looks garbled: swap in a cleaner nearby quote covering the same point, or fold the point into `## Key Points` in your own words instead. Never silently "correct" the quote's wording to what you think was actually meant — that misrepresents the source the other direction.
- **Themes**: useful as a starting tag list for `## Themes & Topics`, verify/expand same as key points.
- **Researchers & Sources Cited**: the draft does NOT extract this — do it fresh from the transcript, exactly as `/process-raw-transcripts` step 2 describes (named individuals cited as sources of expertise, stub new `People/` notes, dedupe against existing ones first).
- Write the note with the same structure as `/process-raw-transcripts` (`## For future Claude`, `## TL;DR`, `## Key Points`, `## Notable Quotes`, `## Themes & Topics`, `## Worth Following Up On`, `## Researchers & Sources Cited`), same signal-density-scaled depth rules, same frontmatter conventions (`type: youtube`/`type: podcast`, `cost-usd: 0`, `signal_density`, `transcript_source` carried from the raw file's header, `ai-first: true`). Save `Research/YouTube/YYYY-MM-DD - <title-slug>.md` (or `Research/Podcasts/...`).
- **Checkpoint after every single file**: mark `processed_ids[video_id] = {"status": "ok", "note": "<path>", "signal_density": "...", "people_discovered": [...]}` in the real `.processed_ids.json` (read-modify-write), remove the entry from `.drafted_ids.json`, and delete the now-consumed draft file from `.drafts/`. Same interrupted-run-loses-at-most-one-file discipline as `/process-raw-transcripts`.

## 3. Sequential concept-linking pass (after the whole batch finishes)
Identical to `/process-raw-transcripts` step 3 — does not parallelize, check `Research/.concepts_absorbed.json` first, actively absorb (not just link), mark absorbed notes with `> [!info] Absorbed into Concepts`, flag real contradictions with `[!contradiction]`, must complete or be cleanly resumed.

Same as `/process-raw-transcripts` step 4.

## 5. Summary
Batch size, relevant/discarded/failed split, signal-density breakdown, **how many signal-density guesses were confirmed as-is vs. corrected** (a real signal for whether the draft model's calibration is improving or degrading over time — worth tracking across runs), **how many `structure_map` guesses roughly held up vs. needed real correction**, **how many `known_low_value_pattern` flags were confirmed vs. turned out to be a false positive** (tracks whether the deterministic pattern list is still accurate or needs a new entry), **repeat-content breakdown** (how many videos were flagged by `find_repeat_candidates.py`, how many actually turned out to add new material vs. genuinely nothing new), dedup breakdown, concepts created/deepened, new `People/` stubs, rollup notes updated, how many drafted-but-unfinished files remain, and how many raw files still have no draft at all (still waiting on the Stage-6-alt timer).

**Anti-fabrication:** identical bar to `/process-raw-transcripts` and every other ingestion command in this vault — verbatim quotes only from the actual raw transcript text you personally read, never invent a gap-fill fact, and never let a draft's own claim substitute for your own verification. **This now explicitly includes `lite_file`**: reading the filler-stripped copy by default (idea #2 above) is a token-efficiency choice, not a relaxation of this rule — any quote that goes into the note must be confirmed against `source_file` (the real untouched raw transcript), never against `lite_file` alone, before it's written down. "Verbatim" means exact-substring-of-the-source, not "trust it's coherent" — see the whisper-mangled-quote warning in step 2 above; `notable_quotes_verified` having passed the script's mechanical check is not the same as it being a sane quote to publish.
